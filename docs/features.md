# Features

What Orivon does today, one line each. [`roadmap.md`](roadmap.md) says what is expected next and
what is later; [`known-limitations.md`](known-limitations.md) says what each feature does not do;
[`planning/compatibility-matrix.md`](planning/compatibility-matrix.md) says what a ported app can
rely on, row by row. A new feature adds its line here when it lands.

## Apps and the platform

- **Capability broker**: an app's manifest, the person's grants, and per-origin enforcement on every call.
- **`orivon.*` capability API**: the interface apps are written against, as types in `src/contracts/`.
- **Report a problem with a site**: a site whose manifest names `support.issues`, an `https://` address, has a "Report a problem with this site" row in its site popover, installed or not, which opens that address in a new tab; a site that names none shows no row. A publisher who takes reports on a tracker of its own says so there.
- **App loader**: fetch a manifest from a URL, cache the bundle hash-pinned, check its integrity, and ask once in plain words before the app runs.
- **`orivon-node-shim`**: Node's `net`, `tls`, `dgram`, `fs`, `http`, `child_process`, `worker_threads` and `node:sqlite` mapped onto the same capabilities, enough to run a Node web server (Express, Socket.IO) in a tab. An app's `process` and `os` present as Node on Linux (a Node version, no `browser` flag, `linux`, `x64`), so a library takes the path it takes under Node.
- **UDP sockets** (`net.udpBind`) for peer-to-peer protocols a web page cannot open.
- **Ported desktop apps**: FreeTube, Element, The Lounge, AirGap Vault and ASGARDEX run from a name, unmodified, with a bridge file kept in `orivon-ports`.
- **File dialogs for ported Electron apps**: `dialog.showOpenDialog` and `showSaveDialog` answer a path that the app's `fs` calls read and write straight through the file or folder the person picked, with no copy and no real path in the page; the path lasts until the page reloads.
- **WASI and native modules as WebAssembly**: a WASI host over `orivon.fs`, native addons loaded as their WebAssembly build, and `spawn` and `fork` as WebAssembly programs and workers.
- **USB HID devices** (`devices.hid`): an app uses `navigator.hid` for the vendors its manifest names, and the person approves each device; a website picks one in a chooser under Site settings.
- **Embedded sites** (`web.embed`): an app shows another site inside its own page, in an isolated view.
- **Cross-origin isolation on request** (`crossOriginIsolated` in the manifest) for WebAssembly built with threads.
- **Per-app storage isolation** with a disk-usage view.
- **Identity seed and `orivon.secrets`**: a seed kept in the OS keyring and an app's own origin-bound encrypted secret.
- **Links to an app**: a link of a scheme an app lists in its manifest (`magnet:`) opens in the app the person chooses, with the choice remembered per scheme and listed in Settings, and the app's page receives the link.
- **Developer mode**: load an unpacked app from a folder.
- **A published app loads at once, asks beside it, and is checked as it runs**: an `ipfs://`, `ipns://`, `.eth` or https app shows its page straight away as an ordinary website, with no permissions, while it asks what it may do and caches its files beside the question. Grant all, or Close with some switches on, reloads the tab as the app; Close with every switch off leaves the website as it is. Each file the app loads is checked against the hash tree its site declares before the page receives it; one that differs is never delivered, every permission is removed and a security warning is shown. The rest of the app is pinned once allowed.
- **The first visit asks with switches, and the key says what is off**: the question is one panel with a row and a switch for each permission the app asks for, all off, in the same words and icons as the key popup; Grant all lets the app hold every row and Close keeps the rows switched on, and with none on it is a refusal. While an app's permissions are not all granted (a row left off, a question dismissed or refused) the key in the address bar wears a dot, and its popup offers Review permissions for an app that was never let in, which asks again. An unlimited network row says what it is for (connect to any computer, send data to any computer, load from any website), so an app asking for several never shows rows that read alike.
- **The first permission question says why it is asked**: the first question a profile ever shows for an app's capabilities (the first visit's switches, or a later request from a page) carries one line above its buttons: "This is a desktop app. It needs more than a web page may have, so it asks you once." Later questions do not, the buttons are the same, and the camera, notification and other website questions the address bar asks never carry it. A private window has its own first question.
- **A tunnel for an installed app**: an app is set like a website. Its tunnel button in the site-info popup and its card in Settings > Apps offer the same three choices (Off, Nym, your SOCKS5 address), and Settings > Tunnels lists it with its tunnel; the proxy is your own SOCKS5 address (Tor on `127.0.0.1:9050`, say). Everything the app causes to leave this computer goes through its tunnel, a name unresolved; on Nym each app has a mixnet tunnel of its own, which starts when the app first connects and stops some minutes after the last one, and Settings and the app's site-info popover say whether it is connecting, ready or not answering (a Test brings Nym up and says how long it took); a Nym privacy choice, Balanced by default and Strongest if you want Nym's steady decoy traffic at about a third of a processor core for each open tunnel; what the tunnel cannot carry is refused, and the app stops when the tunnel does. A tunnel that cannot run now (no address saved, Nym switched off) is not offered for an app and the page says why. Its updates are not checked and WebRTC is off while the route is on. When the app's page opens a website, or navigates its tab to one, you are asked each time whether the page goes through your tunnel (a temporary tab that keeps nothing once closed) or directly; another installed app whose route is off is offered the tunnel too. A website you open is routed only when you turn a tunnel on for it, or for the whole browser.
- **The tunnel for a website**: the tunnel button at the right end of the address bar, after the Web2, Web2.5 or Web3 mark, opens a list of the tunnels Orivon offers (Nym, built in, and your own SOCKS5 address), each with its logo and a switch, and the switch of the chosen one sends this website through it, for any website; each website keeps its own pick, so one can go through Nym while another goes through the proxy. With no proxy address saved the proxy row holds a field for it, which asks you to confirm and can test it, without going to Settings. The popup has two parts, chosen by a control under its heading: the first is for what it was opened on ("This site", "This app" or "This tab") and the second, "Browser-wide", sets the tunnel of the whole browser with the same switches, and with "Also use for IPFS and Swarm nodes" (more private, but pages from those networks load more slowly). It opens on the first part, and on Browser-wide while the whole browser is on a tunnel and the page has none of its own. Turning a tunnel on browser-wide while some tabs keep a tunnel of their own asks first, naming those tabs, and Cancel or Proceed settles it; turning it off asks nothing. An "Open Tunnels settings" link under the list leads to Settings > Tunnels. The first time a website moves to a tunnel, you are told that it moves to the Nym or proxy profile, that you sign in to it again once, and that what it stores stays apart from your normal browsing, and you confirm. The site then loads, with everything it asks of other hosts, through its tunnel in that profile, one session kept across restarts and shared by every site you put on that tunnel, with one copy of each of your extensions (toolbar button, popup and blockers like uBlock Origin work there, with settings of their own in that profile); the button is purple while the tab is on a tunnel, and the warning colour while the tunnel does not answer. Turning it off returns the tab to your normal browsing and keeps the site's data in the profile; Settings lists every site and app with a tunnel setting of its own under the profile it lives in, and "Remove its separate storage" clears that site's data. A `.eth`, `ipfs://` or `ipns://` site is read through its tunnel too: its gateway blocks, its DNSLink lookup, its name's proofs and its CCIP-Read answers, so the button and the popover show it as fully tunnelled and it does not load when the tunnel is down; a `bzz://` address does not open with a tunnel on for it, because the Swarm node cannot send one site's traffic through a tunnel.
- **Site permissions for an installed app**: an installed app that holds no grant is asked for a location, a notification or a clipboard read as a website is, and the answer is kept; one that holds grants has the permissions of its manifest.
- **A Tunnels section in Settings**: Settings > Tunnels holds the default tunnel, the browser-wide switch, Nym's switch, status and privacy level and its test, your own SOCKS5 address and its test, and the list of sites and apps with a tunnel setting of their own, grouped under the Nym, proxy and direct profiles and Apps; it opens at a row from a link such as `orivon://settings/tunnels#route-everywhere`.
- **A tunnel for one tab**: the tunnel button is on the new tab too. Pressed there it lists the tunnels (Nym and your SOCKS5 address) on its "This tab" part, and the switch you turn on sends the first address you type, and every site you open in that tab afterwards, through that tunnel, with the page's first request already inside it; the button turns purple, and on a website that goes through the tab's tunnel it reads "Set for this tab". The choice lasts until the tab closes: it is not saved as a tunnel of any site, another new tab starts with none, and with the whole browser on the tunnel a switch turned off makes only that tab direct. A site you opened in the tab keeps its sign-ins in the tunnel's profile, apart from your normal browsing. The button answers a tab opened onto an address whose page has not come yet (a link opened in a new tab, a restored tab): it lists the tunnels of the site the tab is opening, after any redirect, or of the tab when it carries a tunnel, as it does once the page is there. A popup a page opened has no button until its page has come.
- **The tunnel for the whole browser**: "Send all of Orivon's traffic through the tunnel" under Tunnels sends every website and app with no setting of its own through the tunnel, and what Orivon sends for itself too (update checks, usage statistics, search suggestions, the Web3 names it reads): through the tunnel or not at all. This computer, the connection to the tunnel and the sites and apps you turn off stay direct; a site you turn off from its popover lives in your direct profile. The IPFS and Swarm nodes and the Ethereum light client connect directly unless you turn on "Use tunnel to run network nodes (such as IPFS and Swarm)" under Tunnels (off by default): off, `ipfs://`, `bzz://` and `.eth` pages load at a normal speed and the networks they ask can see this computer's address and what is asked for; on, they go through the tunnel, as slowly as it is, and their cards say so. Turning the setting over moves no site and signs you out of none.
- **A private window with Nym**: "Open a private window with Nym" in the main menu (`Alt+Shift+N`) opens a private window whose whole browser goes through Nym from its first request, whatever the profile that opened it has chosen. In it the browser-wide switch, the tunnel choice and "Let Nym run" in Settings > Tunnels are shown on and fixed with a line that says why, a site's switch in the tunnels popover is on and fixed, and no site can be set to off. The chip says "Private with Nym", the Private page says what that means, and "Open another private window" there opens another one with Nym. If Nym cannot run (its files are missing, a system proxy is set) pages do not load and say the tunnel did not carry them; nothing goes direct. The dock, taskbar and desktop-entry menus offer only the ordinary private window.
- **Pages and scores on a slow route**: how long Orivon waits for a name's proof, a block, a record or a score depends on the route the request travels, not on a figure written for a fast connection. A transfer that is still arriving is never cut off by a clock; one that stops, or sends nothing in time for its route, is. A file that fails for want of an answer is read again before the page is told it is missing, and a page that finished loading with a file missing says so with a mark in the address bar that reloads it. The Web3 Score keeps asking while a slow route answers, and says it could not reach the provider only after its patience is spent, asking again later.
- **App updates at a name**: an installed app keeps its version until the person accepts a newer one. From the yes, its tabs say "Updating <app>" with both versions, then reload from the network onto the new version; a failed update takes the words away and the old version keeps running.
- **Files as apps**: a local HTML, SVG or PDF file opens in a tab, and a file that links a manifest asks once per run.

## Names, content and trust

- **`.eth` names**: resolved by a light client that proves the name's record on this machine, starting from a checkpoint shipped with the release or stored by an earlier run; when both are over 14 days old, or the beacon server will not start the light client from the one in use, a fresh one (the first block of a recent finalized epoch, one the server serves a bootstrap for) is fetched from two beacon servers and used only if they agree, and Settings says so; Settings > Web3 can swap Orivon's servers for the person's own: up to four Ethereum RPC addresses, tried in turn, and one beacon server, each replacing Orivon's for what it covers, with no fallback to Orivon's when they fail (`.eth` names wait and the status names the server and how to go back); an address on this computer or a home network is reached directly, any other must be `https`, a saved address is shown with its key hidden and kept out of logs and reports, and a private window held to Nym keeps to Orivon's servers; `.eth.limo` and `.eth.link` addresses open as the `.eth` name, in a tab and as the images, scripts, stylesheets and requests a page loads from one (a frame keeps loading through the gateway, since a `.eth` site refuses to be framed by another site). On a computer whose clock is behind or ahead (a wrong time zone is the usual cause), the light client takes the time of the servers it already asks, the median of several that agree, and allows for it inside its own process alone, so it still starts and Settings says how far behind or ahead the clock is; where that is not possible it says the clock is behind or ahead and what to set. The address bar shows `bzz://<name>` when the name's content was found on Swarm and `ipfs://<name>` when it was found on IPFS (`ipfs://` until the name has loaded once on this install).
- **`ipfs://` and `ipns://` addresses**: every block checked against its CID; a protocol registry makes the next protocol an isolated piece of work. IPFS loads from Orivon's own node by default: an IPFS node that Orivon runs on this computer (WebAssembly, in a process of its own, reading only), started when an IPFS address is opened and stopped after ten minutes without use, so no public gateway learns which sites you open. Settings > Web3 chooses between that node and public gateways, and whether the node may ask two lookup services (delegated-ipfs.dev and cid.contact), as well as the IPFS network, who holds a site; both apply at once. The node resolves the host names of its web lookups over DNS-over-HTTPS first, so a network that hijacks DNS does not break them; the names of the peers it dials it asks of Cloudflare's resolvers, over TCP. A provider reachable only through a relay can be fetched from too: the node connects to the relay the provider's record names, which sees the two addresses but not the content. When the node cannot run (a build made without it, a system proxy, a failed start, a tunnel that cannot carry it) the page says why and offers "Load through public gateways" for that one load: no public gateway is ever read without your yes, and nothing is remembered. Settings and the site-info popover say why the node was not used and where the content came from. An IPFS folder with no `index.html` opens as a listing of its entries, as a public gateway shows one: folders first, then files by name, each with its size, a link to the parent, and links that open a sub-folder's listing or download a file under its own name; every block the listing needs is checked like any other, and a size marked ~ is the folder's own claim, not read from the file.
- **`bzz://` addresses and `.eth` names on Swarm**: every chunk checked against its address, feeds followed to their newest signed update, or, for a site opened before, to the last update followed, which is kept on this computer and checked against its signature each time: the page opens at once, even with no node or network, while Orivon looks for a newer update in the background and shows it from the next load (a reload or a later visit); a page being read keeps its version for two minutes, unless another tab loads the same site. Swarm loads from Orivon's own node, never from a public gateway: a Swarm light node that Orivon runs on this computer (WebAssembly, in a process of its own), started when a Swarm address is opened and stopped after ten minutes without use. Swarm is off in a build made without the node, and behind a system proxy; the page then says why. Settings shows the node's state. The chunks a site's pages read are kept on this computer (up to 256 MB of chunks, which take a little over 300 MB of disk; each checked against its address again when read back, on a few threads of their own so the rest of the browser keeps answering meanwhile), so a Swarm site seen before opens without asking the node for them; clearing cached data or all history forgets them.
- **Try again on a page that could not check a site**: the "Cannot check this site right now" and "Cannot verify this name yet" pages carry a Try again button; it asks again at once, though the failed attempt was remembered for a few seconds. Local nodes that cannot start name their reason on the page instead of timing out.
- **DDOC**: a site publishes its bundle hash tree, anchored in its ENS record, and the Web3 Score page shows whether the pinned bundle matches.
- **Web3 Score**: a shield in the address bar for the delivery and connection levels, observed by the machine or judged by a provider the person chooses. The mark at the right end of the address bar (Web2, Web2.5, Web3, or a gray Web? for a Level 2 site no provider has scored) opens the same card under itself, with the row of the site's level marked "This site", so what you are on is explained wherever you are; on a new tab the shield opens the card with no row marked. The card's "How scores work" opens the official docs at `docs.orivonstack.eth`.
- **Web3 Score providers**: static sites built with web3-score-manager, asked by hash bucket so a provider never learns the site.

## The browser

- **Shell**: tabs, address bar, back and forward, and a main menu.
- **Settings** at `orivon://settings`: every feature's controls in one place, with search.
- **Link address**: pointing at a link, or moving the keyboard onto one, shows where it goes in a bubble in the bottom-left corner of the page it is in (the pane's, in a split window); it moves to the bottom-right corner when the pointer reaches it and hides a moment after the link is left. It shows for every tab page, installed apps included, and never during a page's fullscreen.
- **Keyboard**: remappable shortcuts, F6 focus cycling, a focus ring on every control, and caret browsing.
- **Tabs**: reorder, move between windows and tear off; pinned, muted and audible tabs; duplicate; reopen closed tabs and windows; tab search; split view.
- **Tab groups and sleeping tabs**: named, coloured groups that survive a restart, and idle tabs that sleep.
- **Profiles and private windows**: a profile is a separate browser; a private window starts empty and is deleted when closed.
- **Start-up and windows**: the new-tab page, the last session or chosen pages, crash restore, a Home button, window placement, `--orivon-kiosk`, and on macOS the window buttons kept in the tab strip in full screen.
- **New-tab dashboard**: a search box, Orivon Featured apps and every bookmark as a tile. The Featured list is data shipped with the build (an id, name, address, icon, pin and order for each entry); any of its tiles can be hidden or unpinned, with a control that shows on hover and keyboard focus, and "Show hidden" brings the hidden ones back. A profile can be given one app to show first, which the person can remove and which is never put back. Settings > Appearance chooses the picture behind it: the Orivon picture, your own, or none. Your own is a PNG, JPEG, WebP, GIF or AVIF image of up to 20 MB, checked by its contents and copied into the profile (the path you picked is not kept); open new tabs change at once, and going back to another choice deletes the copy. A private window starts with the picture of the profile that opened it. A small "Report a bug" button with a bug icon sits at the bottom right of the page (the window's corner, or after the last row when the window is too short for the page, so it never covers a tile) and opens `orivon://report/` in a tab of its own, or brings the one already open to the front.
- **A package that opens an app on first run**: a copy of the Windows installer or the Linux AppImage renamed for an app (`Orivon-Setup-<version>-x64.freetube.exe`), handed out apart from the release, and the macOS and Linux one-line installs given the app (`... | bash -s freetube`). The first time a new profile runs, the tagged app opens in a tab after the welcome screen, asks what it may do as any app does, and shows first in Orivon Featured. The tag only selects one of a short list of apps; a missing, unknown or malformed one gives the usual first run, and so does a profile that has run before.
- **Welcome screen**: shown once per profile before the dashboard.
- **Address bar**: a Web3 / Web2 switch for what you type (Web3, searched with Explore, by default; Web2, DuckDuckGo or another engine), keywords, suggestions from history, bookmarks and open tabs, a "Not secure" mark for plain http, a name that ends in `.onion` typed with no scheme opens over http (an onion service serves plain http, and Tor encrypts the connection), and a QR code for the page. What you type in a tab's address bar and do not send stays with that tab: it is still there after you click another tab or the page, and comes back as you typed it when you return, until you send it, press Escape, or the tab's page moves on.
- **Page tools**: find in page, print and Save as PDF, Save page as, View page source, screenshots, Picture in picture, and right-click menus with spelling.
- **Reader view and a side panel**: an article in its own tab, read aloud; a panel for bookmarks, history and downloads.
- **Bookmarks**: a bar, folders, a manager at `orivon://bookmarks`, and HTML import and export.
- **History**: by day or by session, searchable, with many-at-once delete and recently closed tabs.
- **Downloads**: a list, pause, resume and retry, and a hold on files that run code.
- **Import** of bookmarks and history from Chrome, Chromium, Edge, Brave and Firefox.
- **Passwords**: a local store encrypted by the system keyring, with save, fill, a generator and CSV import and export.
- **Privacy controls**: third-party cookie blocking, Do Not Track, Global Privacy Control, HTTPS-only, secure DNS (on by default: Quad9, with this computer's DNS as the fallback), a certificate viewer and Clear browsing data.
- **Per-site permissions**: prompts for camera, microphone, location, clipboard and more; a popover, a Settings page, a pop-up blocker, and per-site JavaScript, images, sound and downloads.
- **A switch for everything an app may do**: under Settings, Apps, each installed app has a card with one row per capability it declares, the same rows and words as the key popup, each with a switch that applies at once. Switching one off is remembered, so the app stays on the list to be switched on again; picked files, approved devices and chosen link kinds are switches that are on, and switching one off takes it away. Extra access given to an extension is a switch the same way.
- **Available networks**: the toolbar button opens a card for each node Orivon runs on this computer (the Ethereum light client, the IPFS node, the Swarm node and the Nym tunnel), each with its status, a switch that applies at once, what it does for you, and its figures: memory, CPU and uptime, the latest verified block, requests in flight and data read. A dot on the button says how they are. Switch the IPFS node off and ipfs:// pages load through public gateways; switch Swarm or Nym off and what needs them is refused, never sent another way.
- **Screen sharing**: a picker for a tab, a window or the screen, with a bar to stop.
- **Chrome extensions**, MV3 and MV2, from the Chrome Web Store, a `.crx` or `.zip`, or a folder; full uBlock Origin works.
- **Camera and microphone for an extension**: when an extension's own page (its options page, popup or side panel) asks for the camera or the microphone, Orivon asks you over the window that shows it, once per extension and device. Your answer is kept on the extension's details page, where you can change it or set it back to Ask; a page with no window showing it, such as an offscreen document, is never asked and gets only an answer you already gave, and a private window asks again. A page that checks before it asks (`navigator.permissions.query`) reads that it would be asked, so a wallet's webcam check reaches the question; the same holds on a website for camera, microphone, location, clipboard, MIDI, idle detection and window management, and a block you set reads as blocked.
- **A wallet extension asks in one place**: when you click in a page and its extension needs you to approve, the extension's side panel opens beside the page; when it opens a window instead, that is one popup window the extension finds again, brought to the front for the next request, not a new window each time.
- **Extension controls**: a toolbar menu with pinning, side panels, access sheets and command keys.
- **Extensions in the tunnel and direct profiles**: your extensions run for websites you set to on or to off as they do for the rest, one copy of each per profile and not one per site; the toolbar follows the tab in front. Each profile's copies run only while a site of it is open, so an idle profile costs no memory, and with the whole browser on the tunnel no extension makes a direct request while no excluded site is open. Each profile keeps its own extension settings; side panels and command keys stay with your normal browsing.
- **Run in private windows**: each extension has a switch of that name on its details page, off until you turn it on. A private window then starts with a copy of the extension, its choices and its own storage (so a password manager stays signed in), and nothing it does there is saved back to the profile; a website's `localStorage`, cookies and caches are never copied, and an extension's own `localStorage` starts empty. The Extensions button, its menu and the extensions page work in the private window for what runs there; adding, removing and turning off are done in a normal window. Orivon cannot stop an allowed extension from recording what you visit in a private window, and the line beside the switch says so.
- **Orivon and the operating system**: default browser registration (Settings, or a question the default profile asks once after your first app opens or on your second day of use and then weekly, with "Don't ask again" on every ask), links from other programs (web addresses, and `orivon:open?u=<name.eth or ipfs address>` links, which open that name or address and nothing else), dock and taskbar entries, Share (Copy link, and for `.eth` and IPFS pages Copy web link, an `eth.limo` or `dweb.link` address any browser opens), and Create shortcut.
- **Copied addresses carry a link**: an address copied from Orivon (the address bar, a tab's or the main menu's Copy link, a link's or image's right-click menu, a bookmark, a history row, the side panel, the QR sheet) is also written as a link, so pasting `ipfs://name.eth` into a document or a chat gives the same text linked to `https://name.eth.limo/`, and an IPFS or IPNS address one on `dweb.link`; an ordinary web address and Orivon's own pages paste as plain text, and when several bookmarks are copied together and one of them has such a link, the web addresses among them are links too.
- **About and a task manager**: `orivon://about` and `orivon://tasks`, with a way to end a tab that hangs.
- **What's new**: the first start of a newer version opens `orivon://about/whats-new` once, a list of what that version changed, written into the build from `CHANGELOG.md` (no request is made). A new profile does not get it, nor a start after a downgrade or of a version with no list; Settings > About has a link to it.
- **Real tab icons**, fetched by the main process and handed to the interface as data.

## Reporting and distribution

- **Bug reports**: a form that shows the report in full before Send, an opt-in crash dump, deletion from the server, and a local log of the main process and of what its background processes (the `.eth`, IPFS and Swarm host, the local nodes' hosts, the Nym tunnel) print.
- **Telemetry**: opt-in, with a first-run choice, a Settings switch, a privacy notice and erasure.
- **Packages for Linux, Windows and macOS** on every GitHub release (deb, AppImage, NSIS installer, dmg for Apple silicon and Intel), also published on IPFS. The macOS apps are signed with a Developer ID and notarized by Apple, and a one-line Terminal command installs or updates Orivon there with no Gatekeeper warning.
- **A Microsoft Store package** built with every Windows build and kept for upload to Partner Center (not on the release); a Store install is updated by the Store and looks for no update itself.
- **winget**: every release's Windows installer is offered to winget-pkgs by the release workflow (`Orivon.Browser`, and `Orivon.Browser.Preview` for a pre-release), once the owner has stored the token and submitted the first version of each.
- **Update check**: once a day, on by default (Settings > About turns it off), Orivon asks GitHub whether a newer release (pre-releases included) exists. When one does, a question under the address bar in the window you are using tells you once per version, with "Download from GitHub" (the release page, in a new tab), "Download from latest.orivonstack.eth" (the start page of that name, which downloads the package for your system, in a new tab) and "Not now"; it never raises an operating-system notification, and waits while the window is minimised, full screen or covered by another question. Settings > About keeps the release row until you update. It installs nothing.
- **Run from source** on Linux, Windows and macOS with `npm install && npm start`.
