# Tables 2b to 2d: the `electron` module, the packages that wrap it, and web providers

One part of the [compatibility matrix](../compatibility-matrix.md). The matrix page has this
table in readable form, one row per topic; this page lists every item one by one, for looking up a
single name. It says what works today and nothing else.

## Table 2b: the electron module, export by export

Electron 44's typings list 48 value exports of `require('electron')`. This table has one row for each, in alphabetical order, with a row per functional group under the large ones, then rows for the `<webview>` element, `window.open`, Electron's additions to `process`, the subpath specifiers and `@electron/remote`. Every class an export reaches (`CommandLine`, `Dock`, `WebContents`, `Session`, `Cookies`, `WebRequest`, `ServiceWorkers`, `ServiceWorkerMain`, `Extensions`, `DownloadItem`, `Debugger`, `NavigationHistory`, `WebFrameMain`, `MessagePortMain`, `ClientRequest`, `IncomingMessage`, `Display`, `NativeImage`, the ten `TouchBar` item classes and the IPC event objects) sits under the export that reaches it.

The `electron` family lives in its own package rather than folded into `src/shim/`: [`src/shim-electron/`](../../../src/shim-electron/), reached through the `electron` row of [`module-map.ts`](../../../src/shim/module-map.ts). It exports 23 of the 48 names. Four are partly built: `app` (4 of its 115 members), `ipcRenderer` and `ipcMain` over one same-realm bus, and `safeStorage` (3 of its 8 members work). `dialog` and 14 more refuse when called, `nativeTheme` answers wrongly, and `BrowserWindow`, `Menu` and `Tray` refuse as a desktop-shell surface. Of the 48 exports none is `✅ built`: 4 are `⚠️ partial` (`app`, `ipcMain`, `ipcRenderer`, `safeStorage`), 1 `⚠️ differs` (`nativeTheme`), 18 refuse by name and 25 are absent. A ported app does not run its Electron main process at all ([ADR-0005](../../decisions/ADR-0005-apps-are-url-addressed-not-bundled.md)): the renderer bundle is kept, the tab is the window, and a port replaces what its preload exposed with one bridge script that assigns `window.<name>` (Table 2's fourth family). No bridge script of the five ports imports `electron`, and AirGap Vault's own notes say its renderer imports none (the four other upstream renderers are not checked here), so the rows below describe the package as its own tests exercise it. The middle column says what the page or the shell does instead, and whether that substitute works.

An API the package does not build shows in one of three ways, and the row says which:

- **Refuses by name.** The call throws an `ElectronShimError` that names the API and a reason (`unimplemented`, `desktop-shell`, `ambient-fs`, `not-built`, `not-ready`, `invalid-usage`). Seventeen exports are present as stand-ins that do this for a call one level down: `BrowserWindow`, `clipboard`, `contextBridge`, `crashReporter`, `dialog`, `globalShortcut`, `Menu`, `nativeImage`, `powerMonitor`, `protocol`, `screen`, `session`, `shell`, `systemPreferences`, `Tray`, `webContents` and `webFrame`. `BrowserWindow`, `Menu` and `Tray` refuse only their constructor and a few statics.
- **Reads `undefined`, so a call is a bare `TypeError`.** `app`, `ipcMain` and `ipcRenderer` are plain objects with a handful of members, and every member they lack reads `undefined`; so do the other statics of `BrowserWindow`, `app.commandLine`, `app.dock` and `session.defaultSession.cookies`. No reason is attached.
- **Fails the build.** Twenty-five exports are not in the package's export list: `autoUpdater`, `BaseWindow`, `BrowserView`, `ClipboardItem`, `contentTracing`, `ImageView`, `inAppPurchase`, `IpcMainServiceWorker`, `MenuItem`, `MessageChannelMain`, `net`, `netLog`, `Notification`, `parentPort`, `powerSaveBlocker`, `pushNotifications`, `sharedTexture`, `ShareMenu`, `TouchBar`, `utilityProcess`, `View`, `WebContentsView`, `webFrameMain`, `WebSocket` and `webUtils`. A named import (`import { Notification } from 'electron'`) is rejected by a bundler that checks named exports, as Rollup does. Under `import * as electron`, or a bundler that only warns, the name reads `undefined`. Off the default export the name is a stand-in function: calling or constructing it refuses by name, and any member read off it is `undefined`.

Seven calls that real apps make unconditionally at start-up end the app at launch: `Menu.setApplicationMenu`, `crashReporter.start`, `powerMonitor.on`, `new Tray`, `app.on`, `app.requestSingleInstanceLock` and `app.commandLine.appendSwitch`. Their rows say so. `require('electron')` outside an Orivon tab (a unit test of the app, a plain browser tab) throws a plain `Error` that names `window.orivon`, not an `ElectronShimError`.
