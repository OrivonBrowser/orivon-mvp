# Table 3b: module system, bundling and delivery

One part of the [compatibility matrix](../compatibility-matrix.md), which holds the legend, the
definition of every column and the index of all tables. This page says what works today and
nothing else.

The universe is the 5 CommonJS module-scope names with the `require` and `module` members, the 5 `import.meta` members of Node 24, the import kinds a bundle can contain, the package-resolution fields (`browser`, `node`, `exports`, `main`, `module`), the 9 top-level manifest fields, the 41-extension MIME table, the served limits and headers, and the four delivery environments (installed, granted without installing, developer mode, `.eth` and IPFS); an app is a bundle its own bundler built, the shim resolves nothing at run time, and bundler results are for Vite 7 (the renderer's bundler), esbuild 0.25 and webpack 5.

| Surface | Class | Needed by | Status | Where the answer comes from |
|---|:--:|---|:--:|---|
| `require` as a run-time global | `outside` | every CommonJS package | 🚫 excluded by design | `typeof require` is `'undefined'` at page scope: tabs are `sandbox: true`, `nodeIntegration: false` and `contextIsolation: true`, and the shim writes only `process`, `global`, `setImmediate`, `clearImmediate` and `Buffer` (asserted for a `<webview>` guest, inferred for a page). Inside a bundled CommonJS module every bundler rewrites `require`, so `typeof require` reads `'function'` although no loader exists ([`tab-view.ts`](../../../src/main/shell/tab-view.ts)) |
| `require(variable)`, a computed path | `outside` | plugin loaders, `require(name)` registries, i18n loaders | ❌ missing | esbuild: `Error: Dynamic require of "os" is not supported` at run time. Vite: `Could not dynamically require "os"` at run time. webpack: builds an empty context module, so the run-time error is `Cannot find module` (its build warning text is not measured). A bundler option that turns the set into static imports is the substitute: Vite's message names `dynamicRequireTargets`, and webpack's context modules are not measured |
| `require.resolve` | `outside` | `resolve`-style lookups, `require.resolve('pkg/package.json')` | ⚠️ differs | esbuild: `TypeError: __require.resolve is not a function`. Vite: `ReferenceError: require is not defined`. webpack: returns a numeric module id, not a path. The shim's `createRequire(url).resolve('./x.json')` is string arithmetic on the URL path (`/assets/x.json`) and `resolve('fs')` returns `'fs'` |
| `require.cache` | `outside` | hot-reload helpers, `decache` | ⚠️ differs | esbuild: `undefined`. Vite: `ReferenceError`. webpack: an object. `createRequire().cache` is `{}` |
| `require.main`, and the guard `require.main === module` | `outside` | CLI-and-library entries (`commander`-style) | ⚠️ differs | esbuild: `require.main` is `undefined`, so the guard is `false` and `if (require.main === module) main()` silently never runs. Vite: throws `ReferenceError`. webpack: `true` in the entry module (other modules not measured). A bundler `define` mapping `require.main` to `module` for the entry is the substitute |
| `require.extensions`, `module.paths`, `module.id`, `module.filename`, `module.loaded`, `module.parent` | `outside` | old loaders (`babel-register` style) | ❌ missing | Read `undefined` under esbuild and Vite. webpack gives a numeric `module.id` and an empty `module.paths`, and compiles `require.extensions` to `undefined`; its `module.filename`, `module.loaded` and `module.parent` are not measured. Other members of Node's `module` object (`children`, `path`, `require`, `isPreloading`) are not measured |
| `process.mainModule`, and the idiom `process.mainModule.filename` | `dup` | `app-root-path`-style lookups, `require.main` shims | ❌ missing | The shim's `process` has no `mainModule` and no bundler defines one, so it reads `undefined` and `process.mainModule.filename` throws `TypeError`. [Table 3a](table-3a-globals-and-process.md) has the `process` members ([`globals.ts`](../../../src/shim/globals.ts)) |
| `module`, `exports` at page scope; UMD wrappers | `outside` | libraries with a UMD build | ✅ built | `typeof module` and `typeof exports` are `'undefined'` at page scope, so a UMD wrapper takes its global branch; a bundler's CommonJS wrapper defines both inside each module, where both read `'object'`. The page-scope claim follows from the five names the shim writes and is not measured in a page |
| `__dirname`, `__filename` | `outside` | packages that read sibling files; FreeTube's build | ❌ missing | esbuild and Vite leave the free identifier, so a read is `ReferenceError`. webpack with `target: 'web'` substitutes `'/'` and `'/index.js'`. No value reaches the app's own files: the shim's `fs` root is the app's data directory, not the bundle. A `define` to `'/orivon/app'` would make the read succeed against the data directory only (not measured) |
| `import.meta.url`, `import.meta.resolve` | `outside` | ESM packages that locate their own assets | ✅ built | Chromium's: `url` is the served script URL (`https://<origin>/assets/x.js`), never `file:`; `resolve` is a synchronous resolver over import maps, returning an absolute URL, not Node's package resolution (not measured in a page). esbuild `format: 'iife'` empties `import.meta`, so `url` reads `undefined`: build as `esm` |
| `import.meta.dirname`, `import.meta.filename`, `import.meta.main` | `outside` | ESM packages written for Node 20.11 and later | ❌ missing | Not members of Chromium's `import.meta`: they read `undefined` (from the HTML specification; not measured in a page), so `path.join(import.meta.dirname, 'x')` throws `TypeError` unless the build rewrites them |
| The idiom `dirname(fileURLToPath(import.meta.url))` | `outside` | ESM packages that build their own `__dirname` | ❌ missing | The shim's `url.fileURLToPath` throws `ERR_INVALID_URL_SCHEME` for an `https:` URL, so the standard ESM replacement for `__dirname` throws at load. The shim's `fs` refuses a non-`file:` `URL` object the same way ([`fs/paths.ts`](../../../src/shim/fs/paths.ts)) |
| `module.createRequire` | `dup` | ESM packages that load CommonJS, JSON or addons | ⚠️ partial | [`polyfills/module.ts`](../../../src/shim/polyfills/module.ts): loads a native addon by its `.node` path over emnapi ([Table 5](table-5-native-modules.md)) and refuses every other id, builtins included: `createRequire(import.meta.url)('fs')` throws `OrivonShimError` "a browser bundle resolves its modules when it is built". `.main` and `.extensions` read `undefined` |
| `module.builtinModules`, `module.isBuiltin`, `process.getBuiltinModule` | `dup` | `is-core-module`, `resolve`, builtin feature detection | ⚠️ differs | `builtinModules` lists the 31 mapped Node modules and `electron` and omits the 41 unmapped builtins; `isBuiltin('tty')` is `false`. `process.getBuiltinModule` reads `undefined`, and an optional call `process.getBuiltinModule?.('fs')` is safe |
| Dynamic `import()` of a computed specifier | `outside` | code splitting, plugin systems, locale loaders | ⚠️ partial | Native. A relative or absolute URL of an ES module works; a bare specifier fails. On an installed app the target must be a declared asset, else `404 Orivon: not in the pinned asset set`; `blob:` and `data:` module URLs are refused by `script-src 'self'` ([`path.ts`](../../../src/loader/serve/path.ts), [`csp.ts`](../../../src/loader/serve/csp.ts)). How each bundler treats a computed `import()` is not measured |
| JSON imports | `outside` | most bundles | ✅ built | Bundlers inline them (not measured per bundler). A native `import x from './x.json' with { type: 'json' }` needs `application/json`, which `.json` is served as (not measured in a page) |
| Text and CSS imports | `outside` | `style-loader`, CSS-in-JS, text templates | ✅ built | esbuild bundles `.txt` as text; CSS imported from JavaScript is emitted as a separate `.css` file that the HTML must link, and it must be a declared asset. Inline `<style>` and injected style tags are allowed (`style-src 'self' 'unsafe-inline'`); a stylesheet or `@import` from another origin is blocked ([`csp.ts`](../../../src/loader/serve/csp.ts)) |
| `.wasm` imports and loads | `outside` | wasm-bindgen, `sql.js`, argon2 wasm | ⚠️ partial | Served `application/wasm`, so `WebAssembly.instantiateStreaming(fetch(url))` works under `'wasm-unsafe-eval'` (e2e: [`e2e-served-csp.test.ts`](../../../test/e2e-served-csp.test.ts)). esbuild has no loader for `.wasm` unless set to `file` or `binary`; an ES-module `import` of a `.wasm` is not something Chromium provides (not measured). [Table 3g](table-3g-running-code.md) has the engine features |
| `.node` imports | `dup` | native-addon dependencies | ⚠️ partial | esbuild has no loader (`No loader is configured for ".node" files`); Vite and webpack are not measured. At run time the binary is never fetched: `createRequire(..)('./x.node')` or `process.dlopen` loads a sibling WebAssembly build (`x.node.wasm`, `x.wasm`, `x.wasm32-wasi.wasm`) that must be a declared asset; none found is `ERR_DLOPEN_FAILED` ([`addon/`](../../../src/shim/addon/), [Table 5](table-5-native-modules.md)) |
| Top-level `await` | `outside` | modern ESM | ✅ built | Works in an ES-module bundle (`<script type="module">`). esbuild `format: 'iife'`, or a target below `es2022`, fails the build: `Top-level await is currently not supported` |
| ESM and CommonJS interop for a refused member | `dup` | every CommonJS dependency | ⚠️ partial | A bundled `require('os').userInfo()` refuses by name because each of 23 mapped local modules re-exports a generated stand-in file ([`src/shim/README.md`](../../../src/shim/README.md)). Not covered: the six subpath rows (`fs/promises` 19 members absent, `dns/promises` 45 of 46, `util/types` 7, `timers/promises` 2, `path/posix` 1, `stream/promises` none), the two package rows (`events` 10 members and `stream` 15 read `undefined`), and every data member. With esbuild, `require('fs/promises').cp` and `require('os').constants` are `undefined`, and `import { cp } from 'fs/promises'` or `import { constants } from 'os'` fails the build with `No matching export` |
| `browser` field and the `browser` condition (a web target's default in Vite, esbuild and webpack) | `outside` | every isomorphic library (`ws`, `node-fetch`, `debug`, `iconv-lite`) | ⚠️ differs | A dependency is silently swapped for its browser build, which does not use the shim's `net` or `fs` (measured for Vite only; esbuild and webpack not measured). Vite's default build of a package with `exports` `{ browser, node, default }` bundles the browser entry (575 bytes, no `net`). All five ports build with the web defaults and none with `node`; no document in this repository says which to choose |
| The `node` condition (`resolve.conditions: ['node']`) | `outside` | libraries that need `net`, `fs` or `http` | ⚠️ partial | In Vite, `resolve.conditions: ['node']` makes the same package bundle its Node entry and the shim's `net` (300 KB); esbuild and webpack are not measured for the condition. The Node entry imports builtins: the 31 mapped ones resolve, and the 41 unmapped hit the rows below. Any dependency's own `browser: { "net": false }` mapping is overridden by the alias table in Vite and turns into the empty stub without it (webpack and esbuild are not measured for this pairing) |
| Package fields `main`, `module`, `exports` (conditions `import`, `require`, `default`) and `imports` (`#` specifiers) | `outside` | every dependency | ⚠️ **unspecified** | The app's bundler resolves them at build time and the shim reads none. Only the `browser` and `node` conditions were compared (rows above); the others are not measured. Element's build adds a custom condition (`matrix-org:wasm-esm`) |
| One alias row per specifier (`node:` forms, subpaths, a trailing slash) | `outside` | any bundler that applies the shim | ⚠️ partial | [`module-map.ts`](../../../src/shim/module-map.ts)'s `aliasPattern` is `^(?:node:)?<specifier>$`. `fs/promises` needs its own row, and `util/` (the idiom that forces the npm package) is not captured. Vite and the esbuild plugin honour `node:`; webpack 5 does not: a `resolve.alias` entry `'node:os$'` fails with `UnhandledSchemeError`, and only `NormalModuleReplacementPlugin(/^node:/, ...)` stripping the scheme makes it resolve. A string alias (Vite, esbuild's `alias`) also captures subpaths |
| A specifier with no alias row, under Vite production (the renderer's bundler) | `dup` | the 41 unmapped builtins ([Table 2a](table-2a-node-modules.md)) | ⚠️ differs | Externalised to an empty module with a warning `Module "tty" has been externalized for browser compatibility`. A default or namespace import builds and yields `{}`; `require('tty')` from a dependency yields an object with only `default`, so `tty.isatty(...)` throws `TypeError`; a named import fails the build (`"AsyncLocalStorage" is not exported by "__vite-browser-external"`) |
| A specifier with no alias row, under the Vite dev server | `dup` | developers running `npm run dev` | ⚠️ differs | A `Proxy` that throws on any property read (`Cannot access "tty.isatty" in client code`); dependency pre-bundling only warns and returns `undefined`. Read from Vite's source, not run |
| A specifier with no alias row, under esbuild and webpack | `dup` | FreeTube, Element, AirGap Vault (webpack); this repository's e2e fixtures (esbuild) | ❌ missing | Fails the build: esbuild `Could not resolve "tty"` ("built into node"); webpack 5 `Can't resolve 'tty'`. `platform: 'node'` leaves `require('tty')` in the output, which would throw `require is not defined` in a tab (not measured in a tab). webpack's `resolve.fallback: { tty: false }` turns the failure into an empty module |
| A specifier with no alias row, under the electron-vite preload build, and with no bundler | `dup` | this repository's preload; hand-written pages | ❌ missing | Preload: the builtin stays external, `require('tty')` remains in the output and fails at load, because a sandboxed preload's `require` provides only `events`, `timers`, `url` and `electron`. No bundler: `import 'node:tty'` is not a resolvable specifier in a browser (not measured) |
| An npm package that shares a builtin's name (`punycode`, `process`, `events`, `buffer`, `util`, `assert`) | `outside` | `tr46`, `whatwg-url`, `uri-js`; ports that install `process` | ⚠️ differs | esbuild (browser) and Vite resolve the npm copy instead of the builtin; `platform: 'node'` does not (measured for `punycode`). `require('process')` under Vite is `{}` while the global works, and an app that installs the npm `process` (ASGARDEX, AirGap Vault) gets a second, separate object |
| The shim as something a port can consume | `outside` | every future port of a Node library | ❌ missing | [`module-map.ts`](../../../src/shim/module-map.ts) and the [`src/shim-electron/`](../../../src/shim-electron/) package are used by this repository's renderer build only: `package.json` is private and the one bundler recipe is test support ([`shim-esbuild-plugin.ts`](../../../src/shim/tests/support/shim-esbuild-plugin.ts)). The five ports in `orivon-ports` apply neither ([Table 2a](table-2a-node-modules.md)). A Worker bundle can import `installGlobals(options, self)`, which has no alias row. Whether ports adopt an alias table is provisional; the first port that bundles a Node library's dependency graph against the shim settles it |
| Reading the app's own packaged files: `fs.readFileSync(path.join(__dirname, 'asset.json'))` | `outside` | any package that reads a sibling data file | ❌ missing | Cannot work: `__dirname` is undefined or `'/'`, and the shim's `fs` root is the app's writable data directory (`app-data/<hash>/files`), disjoint from the pinned bundle (`apps/<hash>/code`) ([`origin-hash.ts`](../../../src/broker/grants/origin-hash.ts)). The substitute is `fetch(new URL('./asset.json', import.meta.url))`, or a bundler asset import, with the file declared in `assets` |
| `process.resourcesPath`, `app.getAppPath()`, `app.isPackaged` | `outside` | Electron apps | ❌ missing | `process.resourcesPath` reads `undefined`. The shim's `app` has `whenReady`, `isReady`, `getVersion` and `getPath`, and `getPath` answers `'userData'` and refuses every other name by name ([`app.ts`](../../../src/shim-electron/app.ts)); `getAppPath` and `isPackaged` read `undefined`, so `if (app.isPackaged)` takes the development branch. [Table 2b](table-2b-electron.md) has `app` |
| asar archives | `outside` | Electron apps that read `app.asar` | ❌ missing | No asar layer exists: the bundle is loose, individually hashed files in the app's cache |
| `extraResources` and files beside the bundle | `outside` | Electron apps with `extraResources` | ⚠️ partial | The file must be in the served tree and listed in the manifest's `assets`, then fetched from the app's origin. The ports do this with a recipe's `extraFiles` (FreeTube's `botGuardScript.js`, Element's config file, icons), and `prepare` writes `assets` from the finished tree |
| Manifest location and hint: `/.well-known/orivon.json`, `<link rel="orivon-manifest">` | `outside` | every app | ✅ built | The loader reads the manifest from `<origin>/.well-known/orivon.json`, found through the `<link rel="orivon-manifest">` hint in delivered HTML ([`manifest.ts`](../../../src/loader/manifest/manifest.ts)). The manifest is at most 278,400 bytes (`4094 * 64 + 16 KiB`) |
| Manifest fields `orivonApiVersion`, `id`, `name`, `version`, `entry` | `outside` | every app | ✅ built | All five are required. `orivonApiVersion` is the literal `0`. `id` is 1 to 255 characters and informational (C0 and C1 controls, bidi and zero-width characters and unpaired surrogates are rejected); `name` 1 to 200, self-asserted; `version` 1 to 256 and orderable semver (build metadata is ignored), and one below the origin's floor is rejected at install; `entry` 1 to 1024, a canonical relative path |
| Manifest field `assets` | `outside` | every installed app | ✅ built | Optional. At most 4094 canonical paths (4096 entries less `entry` and the manifest), no duplicates or case or Unicode collisions, not `entry` and not the two reserved `/.well-known/` files; an empty array is rejected. Each path is at most 1024 bytes with no `.` or `..` segment, no backslash, colon or vertical bar, no trailing dot or space and no Windows device name ([`canonical-path.ts`](../../../src/broker/policy/canonical-path.ts)) |
| Manifest fields `capabilities`, `consentGranularity`, `crossOriginIsolated` | `outside` | every app | ✅ built | `capabilities` is required and is [Table 1a](table-1-capabilities.md)'s subject. `consentGranularity` is `'all-or-nothing'` (default) or `'per-capability'`. `crossOriginIsolated` accepts `true` only; `false` is rejected ([`manifest.ts`](../../../src/loader/manifest/manifest.ts)) |
| Any other top-level manifest field (`$schema`, `description`, `icons`, `homepage`) | `outside` | manifests generated by a static host's tooling | ✅ built | Ignored with a warning; the manifest is still accepted |
| MIME table: the 41 mapped extensions | `outside` | every app | ✅ built | [`content-type.ts`](../../../src/loader/serve/content-type.ts) types `.html`, `.htm`, `.js`, `.mjs`, `.cjs`, `.css`, `.json`, `.map`, `.txt`, `.xml`, `.webmanifest`, `.vtt`, `.m3u8`, `.mpd`, `.svg`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.avif`, `.bmp`, `.ico`, `.woff`, `.woff2`, `.ttf`, `.otf`, `.eot`, `.wasm`, `.mp4`, `.webm`, `.mp3`, `.ogg`, `.oga`, `.opus`, `.wav`, `.flac`, `.m4a`, `.aac`, `.pdf` and `.zip` (case-insensitive). `.js`, `.mjs` and `.cjs` are `text/javascript`, `.wasm` is `application/wasm`, `.opus` is `audio/ogg` |
| MIME for every other extension | `outside` | Unity `.data`, Godot `.pck`, ML models (`.onnx`, `.gguf`), `.ts`, `.jsx`, `.csv`, `.md`, `.mkv`, `.mov` | ⚠️ partial | `application/octet-stream` with `X-Content-Type-Options: nosniff`, for an extensionless file too. A module script or stylesheet under an unmapped extension (`.node`, `.bin`, `.glb`, `.wgsl`, `.br`, `.gz`) cannot be typed by the browser and fails (strict MIME checking; not measured); `fetch` reads them fine. Whether an `<audio>` or `<video>` source under `.mkv`, `.mov` or `.ogv` plays is not measured. `.ts` is left unmapped on purpose. The verifier uses the same table |
| Limits on a bundle | `outside` | apps with many small files (a `node_modules` tree shipped as is), media and wasm-heavy apps | ✅ built | 64 MiB per asset, 512 MiB per bundle, 4096 entries (4094 declared assets), 30 minutes for the whole install; assets are streamed to and from disk and hashed in constant memory. The bundle is re-verified once per launch, so a file rewritten on disk during a session is not caught ([`bundle-hash.ts`](../../../src/broker/policy/bundle-hash.ts), [`budget.ts`](../../../src/loader/fetch/budget.ts)) |
| Range requests | `outside` | `<video>` and `<audio>` seeking, wasm streaming | ⚠️ partial | One range (`bytes=a-b`, `a-` or `-n`) gets `206` with `Content-Range`; an unsatisfiable one `416`. A multi-range or malformed header is answered with the whole file (`200`). `HEAD` is supported. The verifier uses the same parser ([`range.ts`](../../../src/loader/serve/range.ts)) |
| Response headers present on a pinned asset | `outside` | every app | ✅ built | `Content-Type`, `Content-Length`, `Accept-Ranges: bytes`, `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Content-Range` on a `206` or `416`, and `Cross-Origin-Opener-Policy` with `Cross-Origin-Embedder-Policy` when the manifest sets `crossOriginIsolated` ([`asset.ts`](../../../src/loader/serve/asset.ts)) |
| Response headers absent on a pinned asset | `outside` | service-worker apps, cache-header-driven code, precompressed builds | ⚠️ partial | `Cache-Control`, `ETag`, `Last-Modified`, `Content-Encoding`, `Cross-Origin-Resource-Policy`, `Access-Control-Allow-Origin`, `X-Frame-Options`, `Permissions-Policy`, `Referrer-Policy`, `Service-Worker-Allowed` and `Timing-Allow-Origin` are never set. Consequences: no HTTP-cache validators (every request is a local read), a service worker's default scope is its script's directory, no `Permissions-Policy` restricts a feature, and Chromium's default referrer policy applies. A denied request answers `404` with a plain-text body and no CSP |
| Precompressed assets (`.br`, `.gz`, Unity and Blazor builds) | `outside` | Unity WebGL, Blazor WebAssembly, `.wasm.br` | ❌ missing | `Content-Encoding` is never sent and `.br` and `.gz` are `application/octet-stream`, so a precompressed boot file is not decoded by the browser; publish these builds uncompressed |
| HTTP methods on the served origin | `outside` | form-post callbacks, `PUT` and `DELETE` clients | ⚠️ differs | The installed origin has no method check: a `POST` to a pinned path is answered as a `GET` (a `POST` navigation to a route-shaped path would get the entry document; not measured), and the body is ignored. Only `HEAD` changes the response. The `.eth` and IPFS verifier answers `405` `only GET and HEAD` ([`serve.ts`](../../../src/loader/serve/serve.ts)) |
| Entry in a subdirectory | `outside` | apps whose entry is `dist/index.html`; routers with a fixed `basename` | ⚠️ partial | `/` answers `302` to `/<dir>/<entry>`, so the app starts at that path and `location.pathname` is not `/`; a router with `basename: '/'` sees a mismatch |
| Client-side routing fallback | `outside` | history-routed single-page apps | ⚠️ partial | On an installed app, a navigation to an unpinned path whose last segment has no `.` gets the entry document, so a reload or deep link to `/a/b` works; hash routing needs nothing. A dotted last segment (`/user/john.doe`, `/v1.2/x`), a subresource or `fetch`, or an unpinned asset gets `404`; `/docs/` serves the entry, not `docs/index.html`. A navigation is recognised by `Sec-Fetch-Mode` or by `Upgrade-Insecure-Requests` with an `Accept` naming `text/html` ([`path.ts`](../../../src/loader/serve/path.ts)) |
| Client-side routing on a `.eth` or IPFS origin that is not installed | `outside` | history-routed single-page apps | ❌ missing | The verifier serves `/` and a directory as its `index.html` (a directory without a trailing slash gets `301`), has no fallback for other paths and no `_redirects` reader, and answers a missing path with an error page ([`unixfs.ts`](../../../src/protocols/ipfs/unixfs.ts)). An installed pin of the same app gets the fallback above |
| Same-origin requests for a path the bundle does not list (`fetch('/api/x')`, XHR, an image or chunk built at run time, a `<link>` to an unlisted file) | `outside` | apps with a same-origin API, server-rendered pages, uploads | 🚫 excluded by design | `404 Orivon: not in the pinned asset set` (or `not a valid canonical asset path`): the origin's own server is never reached from an installed app. The loader only logs a warning naming undeclared same-origin files it finds in the entry document. A backend on the app's own host must be a granted `https.connect` host; a `wss://` to the app's own host goes native to the real network, which `connect-src 'self'` admits (not measured for an installed app) |
| Redirects on the way in | `outside` | apps behind a static host's redirect rules | ✅ built | The loader follows a host's same-origin redirects while installing (`/index.html` to `/`; at most 5 hops, and a redirect to another origin is refused) and pins each asset under the URL it requested, never the redirect's target ([`fetch/README.md`](../../../src/loader/fetch/README.md)) |
| A UI loaded from `file://` or a custom scheme (`location.protocol === 'file:'`, `protocol.registerSchemesAsPrivileged`, `webSecurity: false`) | `outside` | Electron apps that load `index.html` from disk | 🚫 excluded by design | `location` is a real `https` (or loopback `http`) URL, so code that branches on `file:` takes its web branch, and a UI built for `app://` or `file://` must be rebuilt with relative URLs. `webSecurity` is `true` on every tab and cannot be turned off. A granted host is reached without CORS and mixed-content checks, per host: through the routed wrapper on the main frame and, on an installed app, through the partition's handler for every other load ([`tab-view.ts`](../../../src/main/shell/tab-view.ts), [ADR-0007](../../decisions/ADR-0007-cached-bundles-served-at-their-own-origin.md)) |
