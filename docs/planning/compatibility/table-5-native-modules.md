# Table 5: the native-module question, per library

One part of the [compatibility matrix](../compatibility-matrix.md). The matrix page has this
table in readable form, one row per topic; this page lists every item one by one, for looking up a
single name. It says what works today and nothing else.

*Which native packages have an answer on Orivon, and what each answer needs.*

The universe is 299 names of npm packages, name groups and Node modules in seven families: the packages that ship a native addon or a platform binary, the thin wrappers that start one, the loaders and build tools that sit in front of an addon, and, for contrast, the pure JavaScript and WebAssembly packages that stand in for them. Each has a row in its family's table.

**The mechanical answer first.** App code runs with `sandbox: true, nodeIntegration: false`, and native machine code never runs for an app ([ADR-0040](../../decisions/ADR-0040-native-shaped-node-features-run-as-webassembly.md)). A child process is a WebAssembly program or a Worker, never an operating-system process. An app therefore reaches what a native package does by one of two routes.

1. **The package's own WebAssembly build.** In a bundle that imports the `module` shim, `process.dlopen` and `createRequire(...)('<file>.node')` load `<file>.node.wasm`, `<file>.wasm` or `<file>.wasm32-wasi.wasm` from beside that path on the app's origin ([`src/shim/addon/`](../../../src/shim/addon/README.md), [Table 3g](table-3g-running-code.md)). That loader takes a build for one thread. A napi-rs `wasm32-wasi` package is threaded, so it loads through its own browser loader, and the app's manifest sets `crossOriginIsolated: true`. An addon written against V8 directly (`nan`) or with Neon has no build for the loader.
2. **A substitute package** in JavaScript or WebAssembly, which the app's own bundler picks. Orivon's alias table holds Node built-ins and `electron` only and has no entry for any third-party package ([Table 2a](table-2a-node-modules.md)), so every `✅` below that names a substitute assumes the port aliases the package.

An addon with no WebAssembly build fails with `ERR_DLOPEN_FAILED` and `reason: 'excluded'`. The message names the three paths it tried and no substitute, so this table is where a substitute is named. The loaders that look a `.node` file up by platform (`bindings`, `node-gyp-build`) find nothing on a platform that reads `browser`; they have a row in the system family below.

A verdict begins with one of these. `✅` works with the substitute and needs nothing from Orivon, or loads as its own WebAssembly build. `⚠️` works with the limit the cell names. `❌` is blocked on a named missing component, with the table that holds its row, or on a package nobody publishes. `🚫` is impossible by design (an ADR or a capability page excludes it, or the web platform has no API for it), and the cell says what the app does instead. A substitute named here is on the npm registry; whether it runs unchanged in an app tab is not measured unless a row cites a test. The "of 80" counts come from a scan of 80 open-source Electron apps' declared dependencies.
