# Devlog — week of 2026-08-24 (compiled 2026-09-01)

## Team message

**Weekly update:**
- **The browser opens for the first time.** A real window, with tabs, an address bar and a toolbar. Picked the tab design from three mockups before any of it was built
- **Proved the risky part works before building on top of it** — a website streaming video peer-to-peer, from inside the browser, at 10x the speed smooth 1080p needs. This was the one thing that could have killed the whole idea. (One test is still stuck, but on the testing tool, not the browser: launched by hand, video plays fine)
- **Made the project public** at github.com/OrivonBrowser/orivon-mvp, with documentation a developer can follow start to finish without asking anyone
- **Started the permission system** — the part that lets someone say "this app can use my internet connection, but not my files", the way a phone asks before using your camera. It is the one thing Orivon can do that Chrome cannot. Nothing on screen yet
- **Set two working rules**: how code gets written, and what every proposed change has to explain. Both now force the question "what does this actually change for the person using it?"
- **Read the docs cold twice, and both times found something real** — a missing roadmap, and a section describing the project as something it is not. Both fixed
- **The browser now looks like a browser.** Tabs sit up in the title bar, there is a bookmarks bar you can star a page into, sites show their own icon on their tab, and opening a new tab lands on a start page with your bookmarks on it instead of a blank white screen
- **Next: finish the permission system.** It is the last piece before an app can do something a normal browser flatly cannot
