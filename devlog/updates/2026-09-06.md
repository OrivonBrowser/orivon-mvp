# Devlog — week of 2026-08-31 (compiled 2026-09-06)

## Team message

**Weekly update:**
- **The permission system can now actually move data.** For the first time, a real web page running inside Orivon asked to open a connection to the internet, Orivon checked that against what the app is allowed to do, and the data went out and came back, both directions, through a real test server. An address the app was *not* allowed to reach was refused. Nothing on screen yet: the "allow this app to..." popup is not built, so in day-to-day use every app still gets "no". That popup is the next step
- **Apps now install themselves, quietly.** Visit a site that declares itself an Orivon app and the browser downloads the app's files in the background, takes an exact fingerprint of them, and keeps them. Decided this week that there is no popup at that point: you are asked only when the app first tries to *do* something, like a phone app asking for the camera the first time you tap the camera button, not when you install it. Also decided: no total disk limit for installed apps (same as every normal browser), and a site running on your own computer can only be installed if you typed its address yourself, so a malicious page cannot point Orivon at your own machine
- **Decided what happens when a site offers an older version than the one you already have.** That can be an attack (replaying an old version to undo a security fix), so the original design blocked it silently. Reversed: you get warned and choose once, and after that just a quiet notice that never gets in the way
- **Removed a feature that never existed: "Open as app".** Several documents described a menu action that turns a website into an app. There is no such step and there will not be one. An Orivon app is just its address, the whole time. Fixed everywhere it was mentioned
- **Cleared the decision backlog: sixteen open questions, six decided by the owner.** Apps list their own files rather than Orivon guessing; an app that fills its storage asks you for more instead of failing quietly; the bookmarks bar stays hidden until you save your first bookmark; DDOC now stands for Domain Data Ownership *Confirmation*, not Certification. The other ten were engineering calls and were settled without a meeting. New rule: if a question cannot be traced to something a real user experiences, do not ask, decide
- **Review sweeps caught real bugs before they shipped.** An app with file access could write about 250 times its storage limit; the single most important automated test (the one proving an app cannot reach past its permissions) had never actually been running; a bookmark saved just before closing the browser was lost; and in the new networking code, healthy idle connections were killed after 15 seconds and closing a connection could hang forever. All fixed, each with a test that fails without the fix
- **Two writing rules are now enforced by the build, not by trust.** Last week these were rules on paper by choice. This week half the code files had grown long explanatory essays anyway, so there is now a hard limit on comment length and on file size, both checked automatically on every change
- **Also landed, nothing on screen:** the first real installable Linux package, built and launched from the code for the first time; the sign-in surface that lets existing Nostr web clients log in through Orivon; usage stats that only send with consent; and the test app used to prove all of the above

## Voice note cues

- **Changed my mind on enforcement** — last week the call was rules on paper only; this week the comment rule was being followed and the code drifted anyway, so the first two rules got automatic checks. What made the difference: a *budget* is checkable even when *quality* is not.
- **A guard nobody can tell is broken** — two of the automatic checks had never fired once, including the one added the day before for the comment problem. Same shape as the smoke checks that reported green while doing nothing. Worse than no guard.
- **Most of the backlog was never mine to answer** — sixteen queued questions, six changed anything a user sees; the rest were engineering calls dressed as decisions. Also the sixth time a question got explained in language only someone who read the planning docs could follow.
- **The docs said things I never decided** — "Open as app" was described in six places and never existed; silently blocking an older version was a written-down security position that was never the intended tradeoff. Both caught mid-build, by pushing back, not in a review.
- **Every round found what the last one cleared** — hand-reading, hostile reviewers and a real test runner each caught what the others missed; the recurring shape is a confident claim nobody re-ran. One "obviously reasonable" fix was actually backwards, and only a second pass looking for exactly that caught it. Open question: more review, or fewer unverifiable claims?
- **Eleven agents at once, three passes deep** — first run at real scale. The two critical bugs only surfaced because a second, independent pass asked different questions, and a third found the real cause underneath a finding the second had already named. And the mirror-image lesson: an agent's pushback on a review finding was right, but only checking the code yourself made that trustworthy rather than assumed.
