# Devlog — week of 2026-09-07 (compiled 2026-09-13, completed 2026-09-15)

## Team message

**Weekly update:**
- **Orivon installed and ran its first real app, start to finish.** A page says what it is, you read one plain-English box listing what it wants, you answer once — and after that it opens from your own machine, even with the internet unplugged. Last week every app still got an automatic no, because nothing had ever asked. One rough edge left on purpose: on a very first visit the app can still start loading before you have answered
- **Your answer is yours to keep or take back.** What you allow survives closing and reopening Orivon, and you can see and withdraw an app's permissions from a list without having to open the app
- **Caught that the installer could not actually install anything — and fixed it the same day.** Orivon was refusing every download, honest ones included, because of a wrong assumption about how it sees where a file came from. It had gone unnoticed because the test that was meant to prove it used a stand-in; it now drives the real thing
- **Orivon now makes the secure connection itself, so a permission can name a site honestly.** Proven against a real certificate: the real site connects, an impostor using the same name is refused
- **Apps can now find other computers directly** — the piece a file-sharing app needs to discover who to download from. Chrome and Brave refuse this outright, so without it our first app could only find people the slow way everyone else already has
- **Four nights of unattended building, around forty batches of work merged:** files and folders, incoming connections, apps signing you in, each app's data sealed off from every other app's, and an app's own web requests routed through Orivon so pages a normal browser blocks just work. Nothing on screen for most of it — and it ran on thirteen decisions I settled in one sitting and queued up for the automation
- **Caught that I had been told a phase was nearly finished when two thirds of it was not written.** Two of our own documents disagreed with each other and the pessimistic one was right
- **Ran a full security review across the forty changes nobody had checked, and it earned one.** Worst of it: any website could have taken your camera, microphone and clipboard without asking, or shut the whole browser down with a broken image, and a site that redirected you elsewhere kept the first site's cookies. All found and fixed — most of the fixes are still waiting to go in. Two completely separate reviews landed on the same two bugs, which is the most reassuring thing all week; less reassuring, one scan ran out of budget, came back "all clear", and had actually checked nothing

## Voice note cues

- **The phase that was not finished** — I was told the only thing left was the permission box; two thirds of what an app can ask for had no code at all. Two of our own documents disagreed, and the gloomier one was right.
- **The comments are written for the wrong reader** — every source file had more explanation than code, and the excess was our own internal process leaking in. An outsider reads the argument we had before the rule we settled on.
- **Read the first target app instead of guessing** — its whole interface is an ordinary web page, so the compatibility layer we built does nothing for it. One routing decision is the entire difference between it working and not.
- **Parked the idea of streaming desktop apps into a tab** — it would make every desktop app work at once, and it still costs weeks I do not have. It did settle one thing: an app that opens its own window outside the browser is not an Orivon app, however cheap that shortcut looks.
- **Asked for a stop-at-90% rule and built the outcome instead** — nothing can read how much of the allowance is left, so the overnight run slows its own burn and recovers by itself when it runs out.
- **A confident report is not evidence** — three reviewers were well argued and wrong, all reviewing code they were never allowed to actually run; and the scan that said "all clear" had run out of budget halfway and voted on nothing. Zero problems looks exactly like a clean result.
- **The documentation pass belongs to the same night** — thirteen batches into the big landing, six of our own status documents were still describing a browser that could not install anything. Build it into the run next time, not the morning after.
