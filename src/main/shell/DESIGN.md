# `src/main/shell/`: why the code has its shape

This holds why the code here is shaped as it is, and is read only when changing a decision. What is in the directory is in [`README.md`](README.md).

**[`hidden-paint.ts`](hidden-paint.ts) makes the chrome page of a hidden window paint through a debugger's focus emulation, on purpose.** The launch's first window, and one that comes up behind, are created hidden and shown after their first paint (`ready-to-show`). A `WebContentsView` in a hidden `BaseWindow` does not paint on Windows, macOS or Linux: its page reads `visibilityState` `hidden`, `requestAnimationFrame` never runs and `ready-to-show` never comes, so without the hold every start waited for the fallback timer in [`window-frame.ts`](window-frame.ts), a second after the window was created. Measured on Electron 44 on each of the three systems, with a bare hidden window and no debugger on its page: `backgroundThrottling: false` (at creation or afterward), `setVisible` with a marker `View` added and removed (what `attach-view.ts` does for a view in a shown window) and `capturePage` (which fails there, for want of a display surface) change nothing, and `incrementCapturerCount` is gone from `WebContents`. Attaching the debugger and sending `Emulation.setFocusEmulationEnabled` makes the page visible, so it paints and `ready-to-show` follows within milliseconds of its load. A page driven by Playwright has that emulation already, which is why no spec saw the wait, and it is why the test launcher sets `ORIVON_TEST_NO_PAINT_HOLD`, which a test build reads and an ordinary build does not carry: the emulation is one flag on the page with no owner, so ending the hold switches off the driver's too (measured with the detach alone as well, and in either order; the omnibox specs saw the field lose focus). A package started with a debugging port holds like any other. The hold ends right after the window is shown (emulation off, then detach), so the page's focus follows the window as before, and the timer stays as the safety net for a page whose debugger another client holds. The window is still shown only after its first paint: the hold makes that paint happen sooner, never the show.
